- Added the `harness.digestEntriesPerKind` setting, so the continual-harness digest can list more than three memories per kind instead of hiding the rest behind a `+N more` line.
- The digest overflow line now names the withheld entries by title (ranked by relevance, bounded), so the model can tell what already exists without opening the store.
- When the agent has `memory/pages/**/*.md` on disk, the digest's memory section becomes a **page index** (`slug — title` plus a `read when` routing line); the model reads a page body with its normal file tools. Prompt notes, skills, subagent specs, and factory specs render as before, and agents without pages keep the entry render unchanged.
- The index degrades through a fixed ladder (shorten routing lines → drop them → list the four freshest pages per type with `+N more`) so a large corpus cannot inflate the resident prompt. Measured on a 12-page corpus: 847 tokens total versus 869 for the legacy three-entry render.
- The system prompt now describes the page memory model (four types, conclusion first, frontmatter kept intact) where it used to describe the entry store.
- Page-backed sessions report a `memory_index` adoption event (page count, type count, truncation rung only — never slugs, titles, or bodies).
- Memory is page-backed end to end: `create_memory` / `update_memory` / `delete_memory` write `memory/pages/<type>/*.md` with `type`, `hook`, and `status`, an update keeps every frontmatter field the caller omits, and deletion archives the page with a tombstone line instead of unlinking it. `search` and `overview` read the pages, and a query with no searchable term now raises instead of returning an empty list.
- The refine prompt distinguishes optimization (distill, relate, abstract — what a refinement pass may do) from compression, merging, promotion, and deletion (the scheduled dream pass only), and asks for resolvable evidence references.
- The dream pass gained the actions its rules can decide on their own: promotion of an `experience` page with two independent evidence entries, and removal of a page with a short body, no evidence, and no place in any edge. Both refuse when the preconditions do not hold.
- A consolidation pass no longer needs a scheduler: when one is due, the digest writes the pass instruction to `memory/DREAM.md` and spends one line pointing the session at it, so the session runs the pass as a single subagent. `harness.dreamDueHint: false` silences the line.
- `get_harness_state` now shows the pages: the memory kind is projected from `memory/pages/**` on every load and excluded from every save, so a reader sees the pages while the state file never receives a stale duplicate. A page returned by `search` counts one read per process in its frontmatter `weight`, the field the host owns.
- The pass now has the deciding half of consolidation too: `plan_pass` refuses to remove a page younger than two weeks (a brand-new page has no weight yet, so "unread" must not read as "unwanted"), walk seeds order by decayed read weight, and `merge_pages(keep, absorb)` performs a merge the pass decided on — body lines survive once, evidence entries are carried over with their continuation lines, references move to the survivor, and the absorbed page is archived.
